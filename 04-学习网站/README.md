# 04 学习网站 · 像素游戏风关卡地图

纯静态（HTML + CSS + 原生 JS），零构建、零依赖、可离线双击打开。

## 文件

```
04-学习网站/
├─ index.html        页面结构（HUD / 16:9 舞台 / 3:4 状态栏 / 对话框 / 关卡弹层）
├─ style.css          像素风样式（8px 网格、硬边框、扫描线、steps 动画）
├─ app.js             交互：关卡解锁、检验勾选、XP、存档/读档、键盘操作、音效
├─ data/chapters.js   8 章关卡数据（与 02-学习路线 一一对应）
└─ preview.png        桌面版截图（用于作品集/汇报）
```

## 打开方式

1. 直接双击 `index.html`（file:// 可用，数据不走 fetch）。
2. 或起静态服务：`python -m http.server 8090 --directory 04-学习网站`，访问 `http://127.0.0.1:8090`。
3. 或按 `05-FDE部署` 的容器方式上线（推荐，带健康检查）。

## 版式与比例的依据（为什么是 16:9 / 3:4 / 9:16）

参考的是当前公开的主流像素/复古站点设计规范，不是拍脑袋：

| 参考 | 给出的可复用规则 | 本项目怎么用 |
|---|---|---|
| 8-Bit Aesthetic 设计参考（chrislemke/website_designs） | 8px 基准网格、低信息密度、瓦片式构图、固定宽容器 | 全局 `--unit: 8px`，舞台内 16px 网格底纹，一屏只放 8 个瓦片 |
| Kombai「Pixel Hollow」落地页模板 | 固定 100vh 视口 + 4px 基准间距 + 全宽面板 | 舞台按视口高度自适应，间距用 8/12/16 阶梯 |
| Kombai「Pacman Arcade」设计系统 | 黑底 + CRT 扫描线 + 8-bit 字型 + 霓虹点色 | `.crt` 扫描线叠层、方波音效、青/绿/琥珀三色点色 |
| Pixelado（Retro Arcade） | 最大宽度 1280px 居中、8px 间距节奏 | `max-width: 1280px`，主次模块间距 16px |

**比例结论**：
- **主舞台 16:9**：街机/主机横屏的经典比例，也是 8 个瓦片 4×2 排布最经济的画幅；
- **侧栏 3:4**：卡带封面/竖版面板比例，承载状态与能力条，不抢主舞台；
- **移动端 9:16**：竖屏瓦片改为 2×4，保证单列可读（已在 `@media (max-width: 980px)` 落地）。

## 交互

- 鼠标点击瓦片进入关卡；键盘 `↑↓←→` 移动光标、`ENTER` 进入、`ESC` 返回。
- 关卡弹层里逐个勾选 L1/L2/L3 检验；**三项全勾才允许通关**（一章一检验）。
- 通关 → +XP、下一关解锁、状态栏进度条变绿、对话框给出下一步指令。
- `存档` 导出 `ai-quest-save.json`（可换电脑/交给面试官看）；`读档` 导入恢复。
- 进度存 `localStorage`，无后端、无埋点、不外传。

## 像素化的实现要点

- 只用 `3px` 实线边框 + 硬阴影，**全站 0 圆角、0 渐变滥用**；
- 进度条用 `repeating-linear-gradient` 做条纹格，宽高都是 8 的倍数；
- 动画统一用 `steps()` 而非缓动，模拟低帧率；
- 扫描线与暗角用 `mix-blend-mode: multiply` 叠加，不遮交互；
- 尊重 `prefers-reduced-motion`，关闭动画。

## 已知边界

- 数据是静态 JS，改章节内容要改 `data/chapters.js`（或后续接 API）。
- 音效是 WebAudio 方波，部分浏览器需一次用户交互后才允许播放（已 try/catch）。
- 封面截图 `preview.png` 为 986×860 视口拍摄，用于展示；实际页面自适应。


## 接入 API：闸门结果由服务端实跑，不再是本地自说自话

页面上的「一章一检验」原本只是勾选，没法证明 check.py 真的绿了。现在接入了后端：

| 接口 | 鉴权 | 作用 |
|---|---|---|
| `GET /api/gates` | 否（只读） | 返回 8 章闸门报告：状态、通过数、耗时、生成时间 |
| `POST /api/gates/refresh` | Bearer Token | 在服务端重跑 `run_all_checks.py`，约 10–13 秒，返回新报告 |

站点与 API 同源：Nginx 把 `/api/` 反代到 `api:8080`，因此 JS 里直接 `fetch('/api/gates')`，不用硬编码端口、也没有跨域问题。

界面上有三处体现：

1. **瓦片右下角**：闸门通过时显示 `✓ 闸门`，一眼能看出哪几关是服务端真跑绿的。
2. **侧栏 STATUS**：`闸门 8/8 PASS`，旁边是令牌输入框（默认 `dev-token`，与部署的 `APP_TOKEN` 一致）。
3. **关卡弹层**：新增「闸门实测 · 服务端」区块，显示 `PASS 6/6 · 2.42s` 与读取时间。**这是服务端跑出来的，不是本地勾选**——面试时可以直接说这句话。

### 离线降级

`file://` 双击打开时 `fetch` 不可用，页面自动进入离线模式：瓦片不显示闸门标记，弹层提示「file:// 离线模式，未连接 API」，勾选与通关逻辑照常工作。不报错、不白屏。

### 两个必须知道的坑

- **浏览器缓存**：Nginx 对 `css/js` 设了 7 天缓存，改了 JS 一定要改 `index.html` 里的 `?v=1.x` 版本号，否则会出现"接口 200 但页面还是旧的"这种假故障。入口页本身已设 `no-store`。
- **容器时钟**：容器内时钟可能和宿主机差几小时，所以页面只显示「读取于 <浏览器本地时间>」，耗时证据用 `duration_s`，不用绝对时间戳。
