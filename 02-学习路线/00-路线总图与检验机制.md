# 00 · 路线总图与「一章一检验」机制

> 上游依据：`01-JD与岗位标准/01-2026秋招JD扒取报告.md`
> 下游产物：`02-学习路线/第0X章-*.md` + `03-代码实战/ch0X_*` + `04-学习网站`

## 1. 这张图的逻辑

不是"先学数学再学深度学习再学大模型"的学术路线。**是倒着从 JD 往回拆的**：JD 要什么证据 → 证据要什么系统 → 系统要什么知识 → 知识按依赖排序。

```
                     JD（AI 产品 / FDE）
                            │
        ┌───────────────────┴───────────────────┐
        │            一条主线（C1–C6）            │
        └───────────────────┬───────────────────┘
                            ↓
 第01章 基础与边界 ── 第02章 Prompt/Harness ── 第03章 RAG
                            │                     │
                            ├── 第05章 数据/后训练 │
                            ↓                     ↓
                      第04章 Agent/MCP ──────→ 第06章 评测驱动
                            │                     │
                            └──────→ 第07章 全栈服务 ←──┘
                                          ↓
                                第08章 生产部署与 FDE 交付
```

- **依赖关系**：01 是所有章的前置；02 是 03/04 的前置；06 必须在 03/04 之后（没有被测对象就没法评测），但 06 的观念要贯穿全程（评测先行）。
- **每章都是一个"可交付单元"**：学完必须产出一个能给别人看的东西（文档 / 代码 / 数字 / 一页 paper），否则不算过。
- **第 05 章（微调/后训练）是可插拔的**：产品岗权重只有 3%，FDE 岗 5%。时间紧就先做"数据构造 + 评测对比"，不做真训练。

## 3. 「一章一检验」怎么执行

**核心规则：一章不检验通过，不进下一章。** 检验不是"看完视频点个勾"，是三层闸门：

### 三层闸门

| 层 | 名称 | 形式 | 谁判 | 通过线 |
|---|---|---|---|---|
| L1 | 概念口试 | 合上文档，对着空气/同伴讲 3 分钟，讲不清的条目打回 | 自评（录音/写要点） | 8 个关键点里能讲清 ≥6 个，且能举 1 个反例 |
| L2 | 代码验证 | 跑 `03-代码实战/chXX/check.py`，输出 PASS 才算过 | 机器（脚本断言） | 全部断言通过，0 失败 |
| L3 | 交付物验收 | 产出物达到验收表要求（有数字、有引用、能复现） | 按 rubric 自评打分 | ≥80 分（满分 100） |

三层全过 → 在网站里点亮该关，解锁下一关。任何一层不过 → 回到本章"回炉清单"，**不许往下翻**。

### 检验卡的标准结构（每章都有）

```markdown
## 【一章一检验】
### L1 概念口试（8 问）
### L2 代码闸门（运行命令 + 期望输出）
### L3 交付物验收（评分表，5 项 × 20 分）
### 回炉清单（不过时先补这些）
### 通关凭证（一句话，能写进简历/作品集）
```

### 防自欺三条

1. **数字优先**：凡是能出数字的（召回率、通过率、P95 延迟、单次成本），不许用"效果不错"代替。
2. **反例优先**：每个概念必须能说出"它在什么情况下不work"——JD 里"理解边界"考的就是这个。
3. **可复现**：任何人 clone 你的目录、按 README 跑一遍，能得到同样的数字。

## 4. 配套代码的运行约定

- 全部 **Python 3.10+ 标准库**，零第三方依赖即可跑通（离线可用）。
- 真实模型调用由 `common/llm_client.py` 抽象：默认走 `MockLLM`（确定性、可复现），设置环境变量后可切真实 provider：

```powershell
$env:LLM_PROVIDER="openai_compatible"
$env:LLM_BASE_URL="https://api.xxx.com/v1"
$env:LLM_API_KEY="sk-xxx"
$env:LLM_MODEL="your-model"
```

- 每章目录下：`README.md`（怎么跑）、`main.py`（本章主实现）、`check.py`（自动闸门）、`data/`（样例数据）。
- 检验统一入口：`python 03-代码实战/run_all_checks.py` 一次跑完 1–8 章闸门。

## 5. 与学习网站的对应

网站的 8 个关卡 = 本文档的 8 章。每关展开后显示：岗位锚点、知识点、检验卡、代码路径。进度存 `localStorage`，可导出存档 JSON（换电脑/给面试官看都能用）。

## 6. 时间与节奏建议（按你的实际情况）

- 你现在是大四 + 有课/毕设：建议 **每周 2 章并行推进的"1 主 1 副"节奏**，主章做到 L2 通过，副章只做 L1。
- 面试前 2 周：停新章，只做 **作品集打包 + 三个高频问题的口述稿**（见第 08 章"交付 SOP"）。
- 每完成一章，往 `01-JD与岗位标准` 的映射表里回填一行"我用什么证据满足了哪条 JD"——这就是简历素材库。
