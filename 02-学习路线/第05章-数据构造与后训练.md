# 第 05 章 · 数据构造与后训练（可插拔章）

> 岗位锚点：「熟悉各类 Post-Training 技术」「微调」「数据与后训练」。产品岗权重仅 3%，FDE 5%——**本章目标是"能讲清 + 能造数据 + 能证明有效"，不是"必须训出一个模型"**。
> 前置：01–03、06（评测口径要先有）。 交付物：SFT 数据集（含构造脚本与质检报告）+ 前后对比评测。

## 1. 后训练三件事，先分清

| 方法 | 干什么 | 数据形态 | 成本量级 | 什么时候用 |
|---|---|---|---|---|
| **SFT（指令微调）** | 教"按什么格式/风格/流程回答" | (instruction, input, output) 三元组 | 中（LoRA 可在单卡跑） | 有稳定输出规范、prompt 教不会时 |
| **DPO / 偏好对齐** | 教"哪个答案更好" | (prompt, chosen, rejected) | 中 | 有明确好坏判断标准时 |
| **RLHF/RLVR（了解即可）** | 用奖励信号优化策略 | 奖励函数/标注偏好 | 高 | 核心模型团队，不是应用岗 |

**产品/交付岗的正确用法**：先穷尽 prompt + RAG + 工具，确实不够再上 SFT；且必须先用评测证明"不是检索的问题"。

## 2. 数据构造：脏活，也是护城河

### 2.1 数据来源（优先级从高到低）

1. **真实业务日志**（脱敏后）：最值钱，覆盖真实问法。
2. **专家手写 golden**：20–50 条精标，定"好答案长什么样"。
3. **模型蒸馏**：用强模型生成 + 人工抽检 20%，成本可控但会继承它的错。
4. **公开数据集**：起步用，注意领域不匹配。

### 2.2 质检六条（每条都能写成断言）

- 格式：三元组齐全、无空字段、长度在区间内；
- 去重：指令级近似去重（归一化后 n-gram 相似度 >0.9 视为重复）；
- 泄漏：训练集与评测集**不得有重叠**（按问题原文+答案双查）；
- 合规：无患者身份信息、无未授权内容；
- 平衡：任务类型分布不畸形（单一类型 >60% 要重新采样）；
- 一致性：同一指令的多个答案不得互相矛盾。

### 2.3 LoRA 参数量（面试常考，手算得出来）

`可训练参数 ≈ 2 × r × d × k × 层数`（r=秩，d/k=被适配矩阵维度）。例：`r=8, d=4096, k=4096, 32 层` → `2×8×4096×4096×32 ≈ 8.6B`？——注意这是全适配所有线性层的量级，实际只适配 q/v 时约 `1/4`。**会用这个公式估显存，比背概念有用**。

### 2.4 训练前后怎么证明有效

固定评测集（第 06 章），三个数：**通过率提升、badcase 修复数、灾难性遗忘（通用能力掉了多少）**。没有第三个数字的微调报告是不合格的。

## 5.【一章一检验】

### L1 概念口试（8 问）

1. SFT 与 DPO 的数据形态差异，各自解决什么问题？
2. 什么情况下"不该微调"？给出 3 个判据。
3. 训练集和评测集泄漏会怎样误导你？
4. 指令去重怎么做，阈值怎么定？
5. LoRA 的 r 调大有什么代价？为什么通常 8–64 够用？
6. 怎么判断"灾难性遗忘"发生了？
7. 蒸馏数据的两个风险是什么，怎么抽检？
8. 一份合格的微调报告必须含哪三个数字？

### L3 交付物验收（5 项 × 20 分）

| 项 | 要求 |
|---|---|
| 数据集 | ≥200 条 SFT 样本，字段规范，附质检报告 |
| 防泄漏证据 | 交叉查重的脚本与结果 |
| 估算能力 | 手算一次 LoRA 参数与显存，能讲清假设 |
| 对比设计 | 一份"微调 vs 纯 prompt"的实验设计（含指标与止损条件） |
| 表达 | 3 分钟讲清"为什么这个场景值得/不值得微调" |

### 回炉清单

- 说不清 SFT/DPO 区别 → 各找一篇原始论文读摘要 + 数据格式；
- 数据直接开训 → 先跑质检六条，通常能砍掉 30%；
- 没有评测就宣称提升 → 回第 06 章建 golden set。

### 通关凭证

> "我能把业务日志变成合规、无泄漏的 SFT 数据集，并用参数量估算判断这套微调在不在我的预算内。"

## 6. 常见坑

- 把"模型答不对"直接归因为"要微调"——八成是检索或 prompt 问题。
- 评测集里混进训练样本，指标虚高 20 个点，上线打回原形。
- 只报提升不报遗忘，通用能力掉一半没人发现。
- 数据量崇拜：200 条高质量 > 2 万条蒸馏垃圾。
