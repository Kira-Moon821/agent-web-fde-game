# 第 02 章 · 提示工程与上下文 Harness

> 岗位锚点：「了解提示工程技巧」「具备 Harness 架构思维，能设计可扩展的产品方案」「上下文窗口管理」「Prompt/Benchmark/Badcase 优化」。
> 前置：第 01 章。 交付物：分层 Prompt 模板 + 上下文预算表 + badcase 回归集。

## 1. 先纠正一个认知

Prompt 不是"写一句话让模型听话"，而是**一套可版本化、可评测、可回滚的工程资产**。JD 里写"Harness 架构思维"的人，要的不是你会写咒语，而是你能否设计"模型外面那一层壳"：怎么组织上下文、怎么给工具、怎么兜住失败、怎么度量好坏。

> 一句话：**Harness = 上下文装配 + 输出约束 + 失败兜底 + 评测闭环。** 四件套缺一件就是 demo。

## 2. 核心知识

### 2.1 分层 Prompt（五层结构）

```
L0 角色与边界   ：你是谁、能做什么、绝不做什么（合规红线）
L1 任务定义     ：输入是什么、要产出什么、成功标准
L2 上下文数据   ：检索片段 / 结构化字段 / 历史摘要（带来源标记）
L3 约束与格式   ：输出 schema、长度、语气、禁止项
L4 示例与反例   ：1–3 个正例 + 1 个 badcase 反例（比只给正例有效）
```

**可扩展性**就在分层里：换业务只改 L1/L2，L0/L3 复用，新人接手不用重写。

### 2.2 上下文预算表（必须做成表，不是凭感觉）

| 区块 | 预算占比 | 超了怎么办 |
|---|---|---|
| System（L0+L1+L3） | 15% | 精简措辞，别删约束 |
| Few-shot（L4） | 15% | 减到 2 例，优先保留反例 |
| 检索片段（L2） | 45% | 先重排再截断，保留引用锚点 |
| 对话历史 | 15% | 滚动摘要（把 N 轮压成 3 条事实） |
| 输出预留 | 10% | 由 max_tokens 硬保 |

### 2.3 上下文压缩三招

1. **滚动摘要**：每 6 轮把历史压成"事实清单 + 未决问题"。
2. **结构化替代自然语言**：把聊天记录换成字段表，token 省一半还更准。
3. **检索代替塞满**：超长文档不要全文进 prompt，走 RAG（第 03 章）。

### 2.4 输出约束

- 优先用 **JSON Schema / function calling**，其次用"只输出 JSON，不要解释"，最次才是正则兜。
- 加**自检段**：让模型先列要点再给结论（对结构化任务有效，对闲聊是浪费）。

### 2.5 Badcase 驱动迭代（这是"提示词工程师"和"评测运营"的分界）

流程：`收集 badcase → 归类（知识缺失/指令冲突/格式错误/幻觉/拒答）→ 改 L0–L4 中对应层 → 跑回归集 → 记录版本`。
每条 badcase 必须带：输入、期望、实际、归因、修法、是否回归通过。

## 5.【一章一检验】

### L1 概念口试（8 问）

1. Harness 四件套分别是什么，缺哪件会出什么事？
2. 五层 Prompt 里，哪几层应该跨业务复用，为什么？
3. 上下文预算表怎么定比例，超预算时"先删什么后删什么"，依据是什么？
4. 为什么 few-shot 里放一个反例比放三个正例有效？
5. 滚动摘要会丢什么信息，怎么防止丢掉"未决问题"？
6. 结构化输出三种约束方式的可靠性排序及各自失效场景。
7. badcase 归因的 5 个标签分别对应改哪一层 Prompt？
8. 什么情况下应该"改检索"而不是"改提示词"？

### L2 代码闸门

```powershell
python ch02_prompt_harness/check.py
```

期望：`[CH02] PASS 7/7`。断言覆盖：五层齐全、预算不超限、超限触发裁剪且保留 system、schema 校验拦截、badcase 归因标签覆盖率 100%、版本号可回滚、同一输入两次装配结果一致。

### L3 交付物验收（5 项 × 20 分）

| 项 | 要求 |
|---|---|
| 模板资产 | 一份 `prompts/` 目录，5 层拆分文件 + 版本号 |
| 预算表 | 真实数字（token 估算），不是百分比口号 |
| badcase 集 | ≥12 条，5 类归因齐全，含"修法"列 |
| 回归结果 | 改一版 Prompt 前后的通过率对比数字 |
| 表达 | 能用 3 分钟讲清"我的 Harness 怎么兜住模型的不确定性" |

### 回炉清单

- 只会写一段长 prompt → 拆成 L0–L4 五个文件再拼；
- 预算表是拍脑袋 → 用第 01 章客户端统计真实 token；
- badcase 全是"答错了" → 按 5 类归因重标一遍，你会发现一半是检索问题。

### 通关凭证

> "我把 Prompt 从'一句话'升级成五层可版本化资产，并用 12 条 badcase 做出了第一版回归集。"

## 6. 常见坑

- 把所有规则塞进 system，模型反而漏读——**约束要少而硬，示例要多而具体**。
- 为了让模型"更聪明"而加长 prompt，结果首字延迟翻倍、成本翻倍、准确率没动。
- badcase 只记"错误答案"，不记"期望答案"——没有期望就没法回归。
- 每次改 prompt 不上版本号，两周后不知道哪版最好。
