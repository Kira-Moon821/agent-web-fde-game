# 第 08 章 · 生产部署、运维与 FDE 现场交付

> 岗位锚点：「生产环境部署 AI/GenAI 方案」「对交付效果和 ROI 负责」「进客户现场把模糊需求做成可上线的系统」「推动客户真正用起来」。
> 前置：07。 交付物：容器化部署包 + 监控指标 + 成本表 + 交付 SOP。

## 1. 什么叫"以 FDE 的部署方式处理"

FDE 的部署不是"把代码 push 上去"，而是六段闭环，**每一段都有交付物和验收人**：

| 段 | 名称 | 关键动作 | 交付物 | 验收人 |
|---|---|---|---|---|
| D1 | Discover 需求发现 | 现场访谈、看真实工单、量化基线 | 一页 paper（第 07 章） | 客户业务负责人 |
| D2 | Scope 范围收敛 | 定"最小可验收范围"+ 非目标 | Scope 表（做什么/不做什么/什么时候） | 客户 + 你方 PM |
| D3 | Pilot 试点 | 单场景、单团队、2 周内跑通 | 可点开的 Demo + 首轮评测报告 | 一线使用者 |
| D4 | Deploy 部署 | 容器化、环境隔离、灰度、回滚 | 部署包 + 运维手册 + 健康检查 | 客户 IT |
| D5 | Adopt 采纳 | 培训、埋点、周报、badcase 回流 | 使用率曲线 + 采纳报告 | 客户管理层 |
| D6 | Handover 移交 | 文档、账号、SLA、知识转移 | 移交清单 + SLA 说明 | 客户运维 |

> 关键差别：普通研发交付"功能"，FDE 交付"**用起来的系统 + 可复现的指标 + 能自己维护的人**"。

## 2. 部署技术要点

### 2.1 三层环境

`dev（本地 docker）→ staging（客户内网/UAT）→ prod（隔离 + 审计）`。**AI 应用多一层：模型版本也当环境变量管**（`MODEL_VERSION` 可回滚）。

### 2.2 容器化的最小正确姿势

- 镜像只装运行所需；配置全走环境变量（密钥不落镜像）；
- `HEALTHCHECK` 打 `/healthz`，返回里带模型连通性；
- 日志到 stdout（JSON 行），方便采集；
- 只读根文件系统 + 非 root 用户（toB 安全评审必查）。

### 2.3 灰度与回滚

- 灰度按 **流量比例 + 客户白名单**双维度；
- 回滚触发条件写死：`错误率 >2% / P95 > 8s / 安全类 badcase ≥1` → 自动切回上一版（模型版本 + 镜像 tag 一起回）。
- **模型回滚比代码回滚更容易被忘**，单独列一行检查项。

### 2.4 可观测三件套

| 指标 | 说明 | 阈值示例 |
|---|---|---|
| 质量 | 通过率、拒答率、引用命中率 | 通过率日环比跌 >3pt 告警 |
| 性能 | TTFT、P50/P95 延迟、QPS、错误率 | P95 > 8s 告警 |
| 成本 | 单次 token 成本、日成本、缓存命中率 | 日成本超预算 120% 告警 |

## 3. 成本与 ROI（FDE 的"负责"就体现在这里）

```
月成本 = 调用次数 × (输入token×单价 + 输出token×单价) + 基础设施 + 人力分摊
月收益 = 节省工时 × 人力单价 + 增量收入（要客户认可口径）
ROI    = (月收益 - 月成本) / 月成本
```

**报价前先算单位经济**：一次问答多少钱，一个坐席一天多少次，客户愿不愿意为省下的时间付这个价。算不出来就别谈"赋能"。

### L2 代码闸门

```powershell
python ch08_deploy/check.py
```

期望：`[CH08] PASS 7/7`。断言覆盖：Dockerfile 存在且含 HEALTHCHECK、compose 有 healthcheck 与重启策略、nginx 配置语法可解析（静态检查）、smoke_test 全绿、loadtest 输出 P95、成本表字段齐全且算术正确、回滚脚本可 dry-run。

### L3 交付物验收（5 项 × 20 分）

| 项 | 要求 |
|---|---|
| 部署包 | `docker compose up` 一条命令起站，健康检查通过 |
| SOP | 六段闭环各有关键动作 + 验收清单 + 责任人 |
| 监控 | 三类指标 + 阈值 + 告警文案 |
| 成本表 | 单次/日/月/ROI 四行数字，含假设 |
| 表达 | 10 分钟"交付复盘"讲稿（含一次失败与回滚） |

### 回炉清单

- 只会 `docker run` → 补 compose + healthcheck + 回滚；
- 没有成本表 → 用第 01 章的记账数据算出单位成本；
- SOP 写成技术文档 → 按"谁验收"重写六段。

### 通关凭证

> "我能按 FDE 六段闭环交付一个 AI 系统：容器化上线、可观测、算得清 ROI、能回滚、能移交。"

## 7. 常见坑

- 只部署不埋点，客户问"用了多少、省了多少"答不出来。
- 回滚只回代码不回模型/提示词版本，回滚后行为仍异常。
- 密钥写进镜像或 compose 明文，安全评审一票否决。
- 交付当天没有"使用者培训"，系统上线即闲置——采纳率才是 FDE 的 KPI。
