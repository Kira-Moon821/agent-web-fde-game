# 第 03 章 · RAG 全链路

> 岗位锚点：「知识库搭建」「理解 RAG 的能力边界」「字段级细粒度索引」「能独立完成知识库 case 的文字优化」。
> 前置：01、02。 交付物：可跑的知识库问答（带引用）+ 召回率与答对率两个数字。

## 1. 为什么 RAG 是产品岗的第一硬技能

因为它是**唯一能用"数字"证明你会做 AI 产品**的环节：召回率、答对率、引用准确率、单次成本——四个数一摆，胜过十页 PPT。

## 2. 全链路六步（每一步都有坑）

```
文档 → ①解析清洗 → ②切分(chunk) → ③向量化(embedding) → ④索引(向量+关键词)
                                                            ↓
用户问题 → ⑤检索(召回+重排) → ⑥生成(带引用 + 拒答) → 答案 + 引用 + 置信度
```

| 步 | 要做什么 | 典型坑 | 医疗/专业场景特调 |
|---|---|---|---|
| ① 解析 | PDF/Word/表格/网页统一成段落 | 表格被拍平、页眉页脚混入、扫描件无字 | 化验单、药品说明书要保留"字段—值"结构 |
| ② 切分 | 按语义/标题切，带重叠 | 一刀切 512 字，把定义和条件切散 | 按「章节—条款」切；术语表单独建索引 |
| ③ 向量化 | 选 embedding 模型，批量+缓存 | 中英混排、专业术语被通用模型稀释 | 长文本用「标题+正文」一起嵌入 |
| ④ 索引 | 向量库 + 关键词索引（BM25） | 只做向量，精确术语召不回 | 药物名/ICD 编码走**精确字段索引** |
| ⑤ 检索 | 混合召回 → 重排 → top-k 截断 | top-k 拍脑袋；没有阈值就全塞 | 设"相关度下限"，低于就拒答 |
| ⑥ 生成 | 只用召回内容作答，逐句带引用 | 模型"自由发挥"补全没检索到的内容 | 输出必须带来源段落ID；无来源则拒答 |

## 3. RAG 的能力边界（JD 明确要求"理解边界"）

- **RAG 治"不知道"，不治"不会推理"**：需要多步计算/对比的问题，RAG 只是把材料给它，推理仍靠模型。
- **RAG 治不了结构化聚合**：`统计近三年某药的不良反应例数` 这类，应该走 Text2SQL/接口，不是 RAG。
- **RAG 的召回上限 = 你的切分质量**：切错了，再好的模型也答不对。
- **上下文不是越多越好**：召回 20 段塞进去，准确率常低于精排后的 4 段（"lost in the middle"）。

## 4. 两个必须产出的数字

- **Recall@k**：标准问题里，正确证据落在 top-k 的比例。k=4 时 ≥70% 算入门，≥85% 算能交付。
- **Answer Accuracy**：答案与金标一致的比例（可用第 06 章的 rubric 判）。≥75% 入门，≥85% 可交付。

## 7.【一章一检验】

### L1 概念口试（8 问）

1. 画出 RAG 六步链路，指出哪一步出错会导致"答得流畅但完全错"。
2. 切分粒度怎么定？为什么需要重叠？重叠多少合适？
3. 为什么必须做"向量 + 关键词"混合召回？举一个只做向量就失败的医疗例子。
4. 重排（rerank）解决的是什么问题？没有重排模型时有什么廉价替代？
5. 什么情况下必须拒答？拒答的判定信号有哪些（阈值/无引用/冲突）？
6. RAG 和微调各自解决什么问题，什么场景两者都要？
7. `lost in the middle` 是什么，工程上怎么缓解？
8. 你如何证明"我的知识库比上周好了"？（说出至少 3 个指标）

### L2 代码闸门

```powershell
python ch03_rag/check.py
```

期望：`[CH03] PASS 8/8`，且 `eval.py` 输出 `Recall@4 ≥ 0.70`、`Accuracy ≥ 0.75`。断言覆盖：切分不越界、每个 chunk 有 source_id、混合召回命中、低于阈值拒答、答案 100% 带引用、金标集可加载、指标计算与手工核对一致、重复问题结果稳定。

### L3 交付物验收（5 项 × 20 分）

| 项 | 要求 |
|---|---|
| 链路完整 | 六步都有实现，不是"调个库" |
| 指标 | 两个数字 + 一张"改前/改后"对比表（至少做一次切分或 top-k 调优） |
| 引用 | 每条答案能点到具体段落 ID |
| 边界文档 | 写 1 页"我的 RAG 不擅长什么"（3 个具体问题类型 + 替代方案） |
| 可复现 | 换一台机器跑 `check.py` 仍 PASS |

### 回炉清单

- 召回率低 → 先查切分（80% 的问题在这），再查术语是否被向量稀释，最后才换模型；
- 答对率低但召回高 → 是第 02 章的 Prompt 问题（约束/格式/拒答规则）；
- 答得"很顺但错" → 缺引用强制与拒答阈值。

### 通关凭证

> "我交付了一个带引用、带拒答、带召回率/答对率双指标的医疗知识库问答系统（Recall@4 xx%、Accuracy xx%）。"

## 8. 常见坑

- 用"文档数"当进度指标。**只有指标才算进度。**
- 金标集自己编 20 条就开始调参——要来自真实用户问题（或至少模拟真实问法）。
- 把所有 PDF 丢进去就完事，不检查解析出的乱码。
- 只调 prompt 不调召回，陷入"越写越长"的死循环。
