# 第 07 章 · 全栈工程与交互层

> 岗位锚点：「具备全栈开发能力，能独立完成代码开发与调试」「客户语言与技术语言双向沟通」「一页 paper / PRD / MVP 落地」「客户模拟轮：不许写代码，只靠提问完成需求发现」。
> 前置：01–06。 交付物：能起服务的 API（流式/鉴权/限流/健康检查）+ 一个前端页面 + 一页 paper。

## 1. 全栈对 AI 岗意味着什么（不是"会写前端"）

FDE 要的"全栈"= **能把一个模型能力变成别人能用的服务**，四层：

```
① 模型层：调用/重试/成本/降级
② 服务层：API 契约、流式、鉴权、限流、幂等、错误码
③ 交互层：加载态、流式打字、引用展示、拒答提示、失败可重试
④ 交付层：一页 paper、部署包、运维手册
```

产品岗至少要能做 ②③④；FDE 岗四层全包。

## 2. 服务层设计要点

### 2.1 API 契约（写清楚才好交付）

```http
POST /api/chat
Authorization: Bearer <token>
Idempotency-Key: <uuid>
{"session_id":"s1","message":"...","stream":true}

200 → text/event-stream: data: {"delta":"..."} \n\n ... data: {"done":true,"citations":[...],"cost":{...}}
4xx/5xx → {"error":{"code":"RATE_LIMITED","message":"...","retry_after":3}}
```

**错误码是最容易被忽略的交付物**：`AUTH_FAILED / RATE_LIMITED / CONTEXT_OVERFLOW / MODEL_TIMEOUT / UPSTREAM_5XX / BAD_INPUT`。前端每个码都要有对应文案。

### 2.2 流式（SSE）

- 首字延迟（TTFT）比总时长更影响体感；
- 流式要处理"中途断开"：客户端重连用 `session_id + 最后序号`；
- 流式下**成本要在结束时汇总**，不能边流边算准。

### 2.3 鉴权与限流

- 每个 key：每分钟请求数 + 每日 token 配额（toB 交付必须能按客户算账）；
- 限流返回 429 且带 `Retry-After`，别让前端瞎猜；
- 写操作（提交工单、改数据）必须幂等键 + 二次确认。

## 3. 交互层（像素风网站就是这一层的练习）

- 三态必须有：加载 / 流式中 / 失败可重试；
- 引用可点、可展开原文（toB 信任感的来源）；
- 拒答要"说清为什么拒 + 给替代路径"，而不是一句"无法回答"。

## 4. 客户模拟轮：需求发现脚本（面试淘汰率最高的一关）

**15 分钟访谈模板（不许开编辑器，只提问）**

1. 现状：现在这件事谁在做？一天做几次？一次多久？（量化基线）
2. 痛点：最烦的是哪一步？错一次代价多大？
3. 数据：材料在哪、什么格式、谁有权访问、能不能出样本？
4. 成功标准：怎样算"这个系统有用"？用哪个数字衡量？
5. 约束：合规/审计/不能碰的系统/预算上限/上线时间。
6. 决策链：谁签字？谁是反对者？他最担心什么？
7. 收口："如果两周后给你一个能在 X 场景跑通、Y 指标达到 Z 的版本，够不够进入下一步？"

> 需求发现的目的不是"问全"，是**当场把模糊需求收敛成一个可验收的最小范围**。

## 5. 一页 paper 模板（toB 交付的标准件）

```
1. 背景与现状（3 行，带数字）
2. 目标与非目标（明确不做什么）
3. 方案（一张流程图 + 3 个关键决策及理由）
4. 指标（业务指标 / 质量指标 / 成本指标）
5. 风险与兜底（模型不确定性、合规、数据权限）
6. 里程碑（2 周 pilot / 4 周 上线 / 后续）
```

## 7. 配套代码

```
03-代码实战/ch07_service/
├─ app.py        # 标准库 http.server：SSE 流式 / Bearer 鉴权 / 令牌桶限流 / 幂等 / 健康检查 / 指标

├─ paper.md      # 一页 paper 模板（填好一个医疗问答的样例）
├─ check.py
```

```powershell
python ch07_service/check.py          # 闸门：起服务→打接口→断言→关服务
python ch07_service/app.py 8080       # 手动起服务
python ch07_service/client_demo.py    # 另开窗口，看流式效果
```

零第三方依赖（不装 FastAPI 也能跑），生产替换成 FastAPI/Go 时契约不变。

## 8.【一章一检验】

### L1 概念口试（8 问）

1. 一个 AI 服务的四层职责，你负责哪几层？
2. 为什么 AI 服务必须返回"结构化错误码"？举两个前端处理差异。
3. SSE 中途断线怎么保证不重复扣费、不重复作答？
4. 限流为什么按"token 配额"而不只按 QPS？
5. 写操作为什么必须幂等键？
6. 需求访谈里，哪三个问题能最快把范围收敛？
7. 一页 paper 里"非目标"为什么必须写？
8. 你怎么向不懂技术的客户解释"模型有 5% 会答错"？

### L2 代码闸门

```powershell
python ch07_service/check.py
```

期望：`[CH07] PASS 8/8`。断言覆盖：无 token 401、超额 429 且带 Retry-After、SSE 分块可解析且以 done 结束、重复幂等键不重复计费、健康检查 200、指标端点含 qps/p95/cost、超长输入返回 CONTEXT_OVERFLOW、错误响应是合法 JSON 且含 code。

### L3 交付物验收（5 项 × 20 分）

| 项 | 要求 |
|---|---|
| 服务可跑 | 一条命令起服务，另一条命令打通用例 |
| 契约文档 | API 文档含错误码表与示例请求/响应 |
| 交互闭环 | 一个前端页面（可用第 04 章网站）完成流式展示 + 引用 + 失败重试 |
| 一页 paper | 真实填写，含指标与风险，非模板留存 |
| 访谈演练 | 录一段 15 分钟需求访谈（可找同学扮演客户），自评是否收敛出范围 |

### 回炉清单

- 只会写 demo 接口 → 补错误码、限流、幂等三件；
- 前端只有加载圈 → 补流式与失败重试；
- 一页 paper 写成八页 → 砍到 6 段，每段不超过 3 行。

### 通关凭证

> "我能把一个模型能力封装成有契约、可计费、可限流的服务，并用一页 paper 把它卖出去。"

## 9. 常见坑

- 用 200 返回错误内容（`{"code":0,"msg":"失败"}`）——前端无法做差异化处理。
- 流式没有结束标记，前端永远转圈。
- 鉴权只做在网关，应用层不校验，内网被绕过。
- 需求访谈变成"我给你讲我的方案"——客户模拟轮直接挂。
